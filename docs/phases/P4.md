# Phase 4: "Analytical Twin" (brief)

The goal: a LoD2 pilot (City Centre / Merchant City) plus per-building analytical attributes, thematic styling, `/scenarios/flood` and a public validation report. Target release is `v0.4.0`.

**Branches.** `phase-4-analytical-twin` comes off `phase-3-moving-city`. There are three workstreams:
- `p4/lod2` in worktree `../clydetwin`;
- `p4/analytics` in worktree `../clydetwin-analytics`;
- `p4/web` in worktree `../clydetwin-web`, started after A and B publish a data contract.

Git rules are the same as P1–P3.

**Constraints (local-first).**
- The pilot LAZ goes on the laptop disk (142 GB free). Budget about 20 GB for the pilot; anything bigger needs Opus approval.
- NGD and Digimap BHA need accounts Fairuz doesn't have yet. Validation therefore uses open references now: published landmark heights, LiDAR DSM residuals (roof surface vs DSM) and LoD1 consistency. NGD/BHA validation stays ⏳.
- Hard rule (§4.2): never put NGD or BHA fields in public tiles. A test must enforce it.

## Workstream A: LoD2 pilot (`p4/lod2`)

1. **Pilot AOI.** Use roughly 2×2 km around George Square and Merchant City, set in `pipelines/config.yaml`. Download the Phase 5 LAZ point clouds for that area: verify the collection on the remotesensing.data.gov.scot catalogue, make the download resumable and checksummed, and report the size.
2. **PDAL preprocessing.** Check the classification, and crop to the footprints with a buffer.
3. **roofer (Docker).** Run per footprint (OpenMap Local building footprints) and output CityJSON LoD2.2. If roofer can't run, escalate before trying an alternative.
4. **val3dity.** Report the % valid; the gate is ≥ 95%.
5. **Validation report** (`docs/methods/lod2.md`):
   - RMSE of the roof surface vs the DSM;
   - LoD1 vs LoD2 height comparison;
   - landmarks;
   - a parameter grid search (small) if it improves RMSE.
   The gate target is roof RMSE vs DSM < 0.5 m.
6. **Tiles.**
   - Try **convertwin** as the showcase; fall back to pg2b3dm.
   - Use the same metadata fields as LoD1, plus `lod=2`.
   - Publish to R2 at `lod2/v1/`.
   - LoD1 stays in place; the web hides LoD1 buildings inside the pilot (expose the set of `building_id`s, or a pilot polygon).

## Workstream B: per-building analytics (`p4/analytics`)

All inputs must be open (verify the licence of each and record it in `DATA_LICENSES.md`). If access or licence is unclear, stop and escalate.

1. **Join keys.** OS Open UPRN + OS Open Linked Identifiers → crosswalk `building_id ↔ TOID ↔ UPRN` (OpenMap Local has no TOID; document the spatial-join method and match rate).
2. **X1.**
   - Volume = footprint area × height.
   - Storeys estimate = height / 3.0 m (documented heuristic).
3. **X3 flood exposure.** For each building, the SEPA flood map likelihood (high/medium/low; river, coastal, surface water). Use downloadable vector data if open; otherwise sample the MapServer query endpoint politely and document the method.
4. **X6 noise.** Scottish Noise Mapping Round 4, Glasgow agglomeration (road/rail Lden band at the façade, approximated by the max over a footprint buffer).
5. **EPC.**
   - Source: the Scottish EPC open dataset.
   - Aggregate per building (median rating, count); **no address columns in any public output** (enforced by a test).
6. **HES heritage.** Listed building / conservation area flags (HES open data).
7. **Data Zones 2022 + SIMD + population.** Produce a choropleth-ready GeoJSON or vector file, and document the DZ2011 → 2022 lookup and its limits.
8. **Output contract.**
   - `build/analytics/buildings_attrs.parquet` keyed on `building_id`.
   - A schema doc in `docs/methods/analytics.md`.
   - Rebuild the LoD1 tiles with the new attributes and publish to `lod1/v3/` (new version; never overwrite).

## Workstream C: web (`p4/web`, after A and B)

- Thematic switcher: height, EPC, flood, noise, heritage, with colorblind-safe legends.
- `/scenarios/flood`.
- `/about/methods`.
- Data Zone choropleth.
- LoD2 pilot in `/explore` and `/immersive`.

## Gate

- val3dity ≥ 95%.
- Roof RMSE < 0.5 m vs DSM.
- Public tiles carry no NGD/BHA/address fields (tested).
- LoD2 shows in `/immersive`.
- CI is green, the README is updated, and blog #4 is drafted.
- NGD-based RMSE < 2 m is deferred until there is an account (noted as ⏳).
