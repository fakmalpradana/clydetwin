# Phase 2: "Glasgow Now" (brief)

Goal: the 3D city plus live environmental conditions (weather, river levels, rainfall, air quality), a `/live` page, SEPA flood zones and 24 h charts. Release `v0.2.0`.

Own terrain was already delivered in P1 (v0.1.0), so it is out of scope here except for carry-overs.

## Branches

- `phase-2-glasgow-now`: phase branch, merged to `main` via PR at the gate.
- `p2/backend` (worktree `../clydetwin`): `db/`, `api/`, `collectors/`, `deploy/`, `docker-compose*.yml`, `tests/`.
- `p2/web` (worktree `../clydetwin-web`): `web/` only.

Same git rules as P1: Conventional Commits with scope, atomic commit per task, `docs/PROGRESS.md` updated in the same commit, no WIP, no secrets.

## Shared API contract (both workstreams code against this)

Base URL comes from env `NEXT_PUBLIC_API_URL` (web) and defaults to `http://localhost:8000`. All responses are JSON and all times are ISO 8601 UTC.

- `GET /api/v1/health` returns `{ status, db, sources: { <source>: { last_ok, age_s, stale } } }`.
- `GET /api/v1/stations` returns a GeoJSON FeatureCollection.
  - Feature properties: `id` (e.g. `sepa:<ts_id>`, `meteo:<grid>`, `aq:<site>`), `source`, `kind` (`river_level|rainfall|weather|air_quality`), `name`, `unit`, `latest: { t, value } | null`, `status` (`normal|high|alert|stale|unknown`).
- `GET /api/v1/timeseries/{id}?hours=24` returns `{ id, unit, points: [[t, value], ...] }`. `hours` is capped at 168.
- `GET /api/v1/now` returns a compact summary for the ticker: `{ weather: { temp_c, wind_ms, precip_mm, cloud_low, cloud_mid, cloud_high, t }, rivers: [{ id, name, value, unit, status, t }], air: [{ id, name, pm25, no2, t }] }`.

CORS is limited to `localhost:3000`, `clydetwin.vercel.app` and `*.vercel.app` previews (configured via env).

## Workstream A: backend (`p2/backend`)

1. **Compose.** Add `docker-compose.live.yml` with:
   - `timescale/timescaledb-ha` (PostGIS included);
   - `api` (FastAPI, uvicorn);
   - `collectors` (one container, simple scheduler loop);
   - `caddy` (TLS, domain from env; default `<ip>.sslip.io`).
   Keep the existing P1 `docker-compose.yml` (tile-build DB) untouched.
2. **Migrations.** Plain SQL in `db/migrations/NNN_*.sql`, applied in order by a tiny runner (`make migrate`).
   - Schemas: `ref` (stations), `ts` (hypertable `ts.observations(station_id, t, value)` with compression and 30-day chunks), `meta` (`ingest_runs`).
3. **`collectors/common.py`.** Retry with backoff, pydantic validation, idempotent upsert (`ON CONFLICT DO NOTHING`), and a `meta.ingest_runs` row per run. Optional Healthchecks ping if `HC_PING_<SOURCE>` is set.
4. **Collectors.**
   - `weather`: Open-Meteo UKMO, 3×3 grid over the AOI, including `cloud_cover_low/mid/high`.
   - `sepa`: KiWIS station catalogue plus 15-min level and rainfall for Glasgow stations. SEPA currently returns 429 per IP. Handle 429 gracefully (back off, log, mark stale), never hammer it, and keep it behind `ARCHIVE_SOURCES`-style enable flags.
   - `air_quality`: Scottish Air Quality (SAQD) Glasgow sites. **Verify the access method first.** If there is no documented open API, stop and escalate; do not scrape.
5. **Backfill.** `make backfill` imports the R2 `raw/` NDJSON archive written since P1. Keep the daily raw dump to R2 from the VM.
6. **API.** FastAPI implementing the contract above. pytest against a seeded DB (testcontainers, or the compose DB in CI via a service container).
7. **Deploy kit.** `deploy/README.md` with exact VM steps (Hetzner CX22, Docker, `.env`, `make live-up`), plus systemd/compose restart policies and an UptimeRobot target `/api/v1/health`. Do **not** provision anything; Fairuz rents the VM.

## Workstream B: web (`p2/web`)

1. `web/lib/api.ts`: typed client for the contract, with stale detection (`age > 2× interval`).
   - Include a fixture mode (`NEXT_PUBLIC_API_URL` unset → `web/lib/fixtures/*.json`) so the web builds and previews without the VM.
2. `/live`:
   - cards for weather, rivers and air quality, each with a 24 h chart (lightweight; prefer an existing dep or plain SVG);
   - a "last updated / stale" badge;
   - honest labels;
   - mobile-first, with a Lighthouse mobile target of at least 80.
3. `/explore`:
   - a bottom ticker from `/now`;
   - river gauges as 3D entities coloured by status;
   - a weather widget;
   - a flood-zone toggle (SEPA flood maps WMS/MapServer used directly; verify the endpoint and licence, attribute on `/about/data`).
   - Also add the OS Open Rivers and greenspace layers if they are cheap. If they need processing, defer them and note why.
4. `/immersive`: show the river gauges as simple coloured markers (the rule that new data appears in both viewers).
5. vitest for the `api.ts` stale logic and the fixture parsing.

## Carry-overs from P1

- **Versioned tile paths** (`lod1/v1/…`) so immutable caching is safe on re-uploads. This belongs to backend (publish) and web (`tileset.ts`); the backend owns it and pings web.
- Terrain–building alignment on slopes is documented only; no change is required unless it is cheap.
