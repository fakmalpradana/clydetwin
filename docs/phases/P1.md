## Shared data contract (A produces, B/C consume) — `web/lib/tileset.ts` mirrors it
Per-building metadata fields in 3D Tiles: `building_id` (str), `height` (m, = h_p70), `h_max`, `h_p90`, `ground_z_odn`, `ground_z_ellip`, `area_m2`, `height_source` (`lidar|default`), `lidar_year` (int). Encoding (as built, pg2b3dm 2.27): glTF `EXT_structural_metadata` property table + `EXT_mesh_features` (one feature id per building, `_FEATURE_ID_0`); numeric fields are FLOAT32, `lidar_year` INT32 (8-byte types fail validator alignment), `building_id` is the OpenMap Local UUID. Tileset is 3D Tiles 1.1 implicit quadtree (`content/{level}_{x}_{y}.glb`), root `transform` + `region` bounding volume, no external CRS offsets. `height_source` is `lidar` or `default` (default = 6 m).
Local sample tileset (1 km, 179 buildings, George Square / Merchant City): build with `make lod1`, serve with `make serve-tiles` (= `npx http-server build/sample/tiles -p 8081 --cors -c-1`), URL `http://localhost:8081/lod1/tileset.json`. Full city: `make lod1 MODE=aoi`.
Geometry: LoD1 extrusion with ellipsoidal (ETRS89 ≈ WGS84) base heights so both Cesium and three.js place it correctly without per-renderer offsets.
