# Phase 3: "Moving City" (brief, local-first part)

**Goal:** the city moves. Aircraft are live, the Subway is simulated, and there is a 24 h time slider. Later, once the accounts exist: buses (BODS), trains (Rail Data Marketplace), SCOOT traffic and car parks (Glasgow portal).

**Honest labels.** Every moving thing is labelled `live`, `scheduled` or `simulated`. Release target is `v0.3.0`.

**Branches.** `phase-3-moving-city` comes off `phase-2-glasgow-now`. Workstream branches are `p3/pipeline` (worktree `../clydetwin`) and `p3/web` (worktree `../clydetwin-web`). Git rules are the same as P1/P2. When P2 lands on `main`, Opus merges `main` into the phase branch.

**Accounts not yet available:** BODS, Rail Data Marketplace, OpenSky and the Glasgow portal. Do not build against those; their tasks stay ⏳ in PROGRESS.

## Shared contract (additions to the P2 API)

`GET /api/v1/vehicles?kind=aircraft|subway&at=<ISO>` (`at` defaults to now) returns a GeoJSON FeatureCollection.
- Each feature is a Point `[lon, lat, h_ellipsoid_m]`.
- Properties: `id`, `kind`, `label` (callsign or line), `mode` (`live|scheduled|simulated`), `heading_deg`, `speed_ms`, `t`.

`GET /api/v1/tracks?kind=aircraft&from=<ISO>&to=<ISO>` returns `{ id: [[t, lon, lat, h], ...] }` for the time slider. The window is capped at 24 h.

`GET /api/v1/stream/vehicles` is SSE. It sends a `vehicles` event every 5–10 s with the same payload as `/vehicles`.

## Workstream A: `p3/pipeline` (backend + pipeline)

0. **Archive.** Add UK-AIR to `collectors/archive.py` (reuse the P2 collector's fetch/parse; no duplication). Make it the default in `.github/workflows/archive.yml`, then update `docs/data-archive.md`. This lets the 72 h P2 soak be proven from the 24/7 GitHub Actions archive plus `make backfill`, with no laptop uptime.
1. **AOI extended to Glasgow Airport** via `pipelines/config.yaml` only.
   - Add a second AOI entry: Renfrewshire airport corridor as a bbox or polygon. Document it.
   - Re-run `make lod1` and terrain for the new area.
   - Report the counts, default-height % and validator result.
   - Publish under `lod1/v2/` and `terrain/v2/`; never overwrite `v1`.
2. **Aviation.**
   - Poll adsb.lol every 20–30 s over a ±40 km bbox around EGPF, respecting its terms and rate limits (verify; escalate if unclear). The layer is ODbL, kept separate.
   - Store in `ts.aircraft_positions` (hypertable, 30-day retention).
   - Convert altitude to ellipsoidal height. Barometric altitude needs QNH: use METAR EGPF (free AviationWeather API) if cheap, else geometric altitude when present. Document the choice.
   - Detect EGPF arrivals and departures as simple events.
   - OpenSky comes later as an optional source.
3. **Subway (simulated).**
   - Take the OSM `railway=subway` geometry (Overpass, ODbL) and the 15 NaPTAN stations.
   - Use the published headway (verify from SPT); run inner and outer circles.
   - Produce a deterministic position for any `at`.
   - Store the static geometry in `ref`; compute positions on request.
4. **API.**
   - Implement `/vehicles`, `/tracks` and the SSE stream.
   - pytest covers the subway sim determinism, adsb parsing, altitude conversion and the endpoints.
   - Credentials never reach the browser.
